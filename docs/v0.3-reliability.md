# v0.3 reliability hardening

## Implemented

- Remote sources are limited to canonical GitHub HTTPS URLs and full 40-character commit SHAs.
- Git initializes an empty temporary repository, disables the `file` protocol, fetches the exact object, and checks out detached `HEAD` at that SHA. The installer never runs hooks, skill scripts, or submodules.
- Source trees reject traversal, symlinks, special entries, more than 512 files, and more than 10 MiB. A deterministic SHA-256 tree hash is recorded in `.ultimate-agent-kit.lock.json`.
- Installation uses a unique staging directory and a backup rename. A replacement failure restores the original directory when the process remains alive.
- Per-scope exclusive operation locks prevent simultaneous install/update operations. Update supports `--dry-run` and verified replacement using the same pipeline.

## Evidence

- Windows local test run: 9 tests passed, including an isolated public-GitHub install and malicious traversal/symlink cases.
- CI is configured for Ubuntu, Windows, and macOS; it has not been executed on hosted runners during this local task.
- Codex discovery evidence: `C:\Users\KRR\.codex\skills\apple-design-expert\SKILL.md` exists with valid frontmatter. This is discovery evidence, not a live skill-runtime test.

## Known limits and release blockers

- A process killed between destination rename and lockfile update has no durable recovery journal yet. Do not claim crash-safe transactional recovery.
- Failure injection for OS-level rename, disk-full, and lockfile-write faults is not yet implemented; these require an injectable filesystem layer.
- Runtime behavior has not been tested in Codex, Cursor, Gemini CLI, or Claude Code.
- Public `agent-skills` catalog pins the currently published commit `61ae451`; newer local commits require an approved push before catalog advancement.
